# ClipBox 替代 Win+V 规格

> 状态:草稿 v1(已根据使用者回答修订)
> 范围:仅供个人使用,不做跨设备同步,不接管系统 Win+V。

## 1. 定位

一个仅供个人使用、响应速度接近 Win+V、并在搜索、备注、持久化上明显更强的 Windows 剪贴板历史工具。

"轻量"的定义:**响应速度尽可能接近 Win+V**,包括唤起、复制、粘贴三个动作。内存和体积是次要约束。

## 2. 范围

### 2.1 做

- 记录文本和图片剪贴板内容
- 全局热键唤起(固定为 `Ctrl+Alt+V`,已确定)
- 输入即搜索,键盘可完成全部操作
- 选中后写回剪贴板,并自动粘贴到原窗口
- 置顶、备注、标签、来源应用
- 重启后保留历史
- 排除密码管理器等隐私内容

### 2.2 不做(本阶段)

- 接管或禁用 Win+V,不修改系统剪贴板历史设置
- 跨设备同步
- 云端备份或更新检查的自动联网

### 2.3 隔离(不删除代码,不在界面展示)

- 备份导入导出、诊断包、更新检查、存储统计与修复页面
- 理由:与"快速剪贴板"无关,占用代码量大
- 0.3.0 实现方式:设置页分「常规 / 隐私 / 存储 / 高级」四个标签,这些功能全部收进「高级」,打开设置的第一屏看不到;代码保留。

## 3. 性能指标(核心验收)

**原则:先测 Win+V 的基线,再定 ClipBox 的目标。** 下表中 Win+V 的数值需要你在本机实测后填入,我不预设。

| 指标 | 测量方法 | Win+V 基线 | ClipBox 目标 |
|---|---|---|---|
| 唤起延迟 | 按热键到列表第一条可见(录屏逐帧或计时) | 待测 | ≤ 100ms(目标);若 Win+V 更快,则以 Win+V 为准继续收紧 |
| 选中到粘贴完成 | 回车到目标窗口出现内容 | 待测 | ≤ 100ms(不含目标程序自身的响应时间),且去掉固定 Sleep |
| 粘贴成功率 | 记事本、Chrome、VS Code、一个管理员窗口,各 20 次 | 待测 | 全部成功;失败时必须有提示 |
| 启动到可用 | 双击到热键可用 | 待测 | ≤ 1 秒 |
| 搜索响应 | 1 万条历史中输入关键词到结果刷新 | 不适用 | ≤ 100ms |
| 空闲内存 | `check_mem.ps1` 运行 10 分钟后取值 | 待测 | 待实测后定 |

## 4. 交互与外观(对齐 Maccy,源码为准)

> 依据:`https://github.com/p0deje/Maccy` 源码(浅克隆于本次调研),文件路径如下标注。
> 本节替代之前草案中与 Maccy 不一致的部分。

### 4.1 唤起与焦点
- 唤起后搜索框即焦点,直接打字即搜索(`Maccy/Views/HistoryListView.swift` 第 121 行 `searchFocused = true`)。
- 唤起热键:`Ctrl+Alt+V`(已确定)。

### 4.2 选择与动作(`Maccy/Observables/History.swift` 的 `select`)
| 操作 | Maccy 行为 | ClipBox 对齐 |
|---|---|---|
| 单击(使用者需求,覆盖 Maccy 默认) | 复制并粘贴回原输入框,窗口自动隐藏 | 与 Maccy 默认不同,以使用者需求为准(2026-10-12 确认) |
| 回车(无修饰键) | 关闭窗口,写入剪贴板;若开启"自动粘贴"则粘贴 | 同 Maccy |
| Option+回车 / Option+单击 | 复制并粘贴 | ClipBox 用 `Alt+回车` / `Alt+单击` 对应 |
| Shift+Option+回车 | 无格式粘贴 | ClipBox 暂不做(文本已是纯文本) |
| 数字键 / Command+数字 | 快速选第 n 条 | ClipBox 作为后续项 |
| Option+Delete | 删除 | ClipBox 用 `Delete` 键,保留二次确认(已有) |
| Option+P | 固定 | ClipBox 用 `P` 或现有固定按钮 |
| Esc | 关闭窗口(`KeyChord.swift:124`) | 同 Maccy:有搜索词先清空,否则关闭 |
| 清空 | 菜单 Clear;Option+Command+Delete 清空未固定项 | ClipBox 保留已有清空按钮 |

### 4.3 历史与检查
- 历史上限默认 **200 条**(`Defaults.Keys+Names.swift:71`)。ClipBox 目前默认值以设置为准,需对齐或说明理由。
- 剪贴板检查间隔 **0.5 秒**(`clipboardCheckInterval`)。ClipBox 目前用系统 `WM_CLIPBOARDUPDATE` 事件,无需轮询,这是 Windows 上更优的做法,保留。
- 搜索默认模式 **exact**(`searchMode` 默认值,`Defaults.Keys+Names.swift:63`)。ClipBox 当前为 FTS 子串搜索,语义接近 exact。

### 4.4 外观参数(2026-11-06 按 Windows 实测定稿)

Maccy 的数字是 macOS 的单位,直接照搬到 400×560 的 Windows 弹窗会让一屏只放得下 6 条。下表是**实测后**采用的参数(前端 `App.css` / `App.tsx`):

| 参数 | 采用值 | 说明 |
|---|---|---|
| 窗口 | 400×560,固定 | 不随条目数变化(第 28 行决定记录) |
| 顶部 | 单行 36px:搜索框 + 固定/快捷键/设置/关闭 | 标题栏与搜索框合并;去掉最小化按钮。搜索框本身无边框,净高 28px |
| 工具栏 | 30px:全部/文本/图片分段控件 + 标签下拉 + 「⋯」菜单 | 「清空未置顶记录」收进「⋯」;快捷键说明收进顶部「?」 |
| 列表项高度 | 文本 32px,图片 48px | 一屏约 15 条(560 − 66 = 494px) |
| 列表项圆角 | 4px | 圆角统一为 4px / 8px 两档 |
| 行内布局 | 序号 · 来源图标(或缩略图)· 单行预览 · 图钉 · 时间 | 时间用 11px,预览 13px,来源应用名移到悬停提示和详情 |
| 序号 | 前 9 行右侧显示 1~9 | 与 `Ctrl+数字` / `Alt+数字` 对应,第 10 行起不显示 |
| 选中项背景 | 系统强调色**不透明实底** | 原规格的「80% 不透明 + 白字」实测只有 3.35:1,不达标 |
| 选中项文字 | 按强调色亮度在白/近黑中取对比度更高者 | 本机强调色 #0078D4 白字 4.53:1;浅蓝 #4ca6ff 用近黑 6.9:1 |
| 置顶标记 | 行内图钉图标 + 淡强调色底(未选中时) | 不再用左侧 2px 竖条,避免和选中态混淆 |
| 搜索命中 | 加粗 | 与 Maccy `highlightMatch` 一致 |
| 图片预览 | 行内 32×32 缩略图 + 「宽×高 · 文件大小」 | 原图在详情页(Space)按需加载 |
| 来源应用 | 16×16 图标(`ExtractIconEx`),取不到时按类型画图标 | 悬停提示仍保留「应用 · 窗口标题」 |
| 图片行信息 | `GetClipImageMeta` 批量读取 DIB 头与文件大小 | 每行最多一次,失败不重试 |
| 字号 | 12 / 13 / 14px 三档 | 字重 400 / 600 两档 |
| 强调色 | 读 `HKCU\Software\Microsoft\Windows\DWM\AccentColor` | 唤起时刷新一次;取不到时用主题默认蓝 |
| 次要文字对比度 | 深色 6.34:1,浅色 5.05:1 | 均高于 WCAG AA 4.5:1(浅色原为 3.72:1) |

> 颜色与字体以系统强调色为基准;亮/暗两套中性色见 `App.css` 的 `:root` 与 `:root[data-theme="light"]`。

### 4.5 功能验收步骤

1. 复制一段文本、一张截图,在 ClipBox 中均可见。
2. 按热键,不点击,直接输入关键词,列表过滤正确(对应 4.1)。
3. 用方向键选中一条,按回车复制;按 Alt+回车则复制并粘贴,在记事本中粘贴出该内容(对应 4.2)。
4. 对同一操作在 Chrome、VS Code、管理员窗口各重复 20 次,记录成功次数。
5. 重启 ClipBox,历史仍在。
6. 从 1Password 等密码管理器复制内容,ClipBox 不记录。
7. 失败场景:目标窗口无法获得焦点时,界面不额外提示(与 Win+V 一致)。内容已在剪贴板中,手动 Ctrl+V 即可;失败原因写入诊断日志。

## 5. 技术决定

### 5.1 图片存储:保留文件,不改为 base64 入库

使用者提出过"先 base64 存储"。我的建议是**不采用**,理由如下:

| 方案 | 优点 | 缺点 |
|---|---|---|
| base64 存入 SQLite | 单文件,备份简单 | 体积膨胀约 33%;每次读库都要带上大字段;数据库变大后整体变慢 |
| 文件存 `images/`,数据库存路径 | 列表查询不带图片数据;与当前设计一致 | 需要保证文件和记录一致(已有"修复缺失图片"功能) |

当前代码已经是文件存储,并且列表只传缩略图,按需加载原图。真正影响速度的是**缩略图生成和列表查询是否阻塞**,应在第 3 步的测量中验证,而不是换存储格式。

### 5.2 粘贴机制

- 去掉固定 `Sleep`,改为轮询 `GetForegroundWindow` 确认目标已成为前台,超时 300ms 后放弃
- 检查 `SetForegroundWindow` 和 `SendInput` 的返回值
- 失败时提示用户手动粘贴

## 6. 待定项

1. **热键(已确定)**:`Ctrl+Alt+V`。当前代码已是此默认值,无需修改。
2. **基线测量**:需要你先用 Win+V 测一次唤起和粘贴速度,把结果填入第 3 节,我才能确定"接近"的具体数值。
3. **空闲内存目标**:待第 2 步实测后定。
4. **剪贴板历史容量**:建议默认保留最近 500 条,超出自动清理非置顶项。

## 7. 实施顺序

0. **测基线**:你测 Win+V 的唤起和粘贴速度;我用 `check_mem.ps1` 测当前 ClipBox 的内存和唤起/粘贴耗时。
1. **粘贴可靠性**:改 `windowutil` 与 `pasteToLastTarget`,去掉固定延时,按第 3 节测量。
2. **唤起速度**:检查窗口显示和数据加载是否阻塞。
3. **运维功能隔离**:依赖分析后从界面隐藏。
4. **搜索与列表**:按第 4 节验收。

每一步完成后更新 `PROGRESS.md`,并按第 4 节验收后才进入下一步。
